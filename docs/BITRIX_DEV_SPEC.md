# Что нужно сделать в Битрикс24 (magssory.bitrix24.ru)

## 1. Приложение
Локальное серверное приложение «HR-портал», без пользовательского интерфейса (только API), с OAuth.

| Параметр | Значение |
|---|---|
| Название | HR-портал |
| Права (scope) | task, user, calendar, im, disk |
| Путь обработчика | `<АДРЕС_ПОРТАЛА>/api/bitrix/handler` |
| Путь для первоначальной установки | `<АДРЕС_ПОРТАЛА>/api/bitrix/install` |

`<АДРЕС_ПОРТАЛА>` пришлём отдельно (будет https).

Установить приложение от имени служебного пользователя «HR-портал», не от личного аккаунта.

## 2. Группа
Создать группу (проект) **«Заявки HR»**. В ней должны состоять: служебный пользователь «HR-портал» и HR-сотрудник.

## 3. Права на задачи
Приложение должно уметь:
- создавать задачи в группе «Заявки HR» (`tasks.task.add`);
- указывать постановщика (`CREATED_BY`) — сотрудника, подавшего заявку. Просим проверить, возможно ли это, и какие нужны права. Если нельзя, сообщите;
- читать задачи (`tasks.task.get`);
- искать пользователей по email (`user.get`);
- подписываться на события задач (`event.bind`, событие `onTaskUpdate`).

## 4. Как портал создаёт задачу (для сверки)
Метод `tasks.task.add`, поля:

| Поле | Значение |
|---|---|
| TITLE | `Тип заявки — Фамилия И. (дд.мм.гггг – дд.мм.гггг)`, например `Отпуск — Иванов И. (01.12.2026 – 14.12.2026)`. Даты, если есть |
| DESCRIPTION | BB-код: тип заявки, сотрудник и должность, отдел, даты, комментарий сотрудника, примечание, ссылки на файлы, ссылка на заявку в портале |
| RESPONSIBLE_ID | HR-сотрудник (id по email) |
| CREATED_BY | сотрудник, подавший заявку (id по email) |
| GROUP_ID | группа «Заявки HR» |

Типы заявок: справка, отпуск/отгул, командировка, техника, доступ. Исполнитель для отдельных типов (например, техника) может быть другим человеком, портал это поддерживает.

## 5. События
Портал сам подписывается через `event.bind` на `onTaskUpdate` с адресом `<АДРЕС_ПОРТАЛА>/api/bitrix/events`. Нужно, чтобы приложение имело на это право (scope task), и события доходили до этого адреса.

Статус задачи → статус заявки в портале:
- новая (2), отложена (6) → «На рассмотрении»;
- выполняется (3), ждёт контроля (4) → «В работе»;
- завершена (5) → «Готово».

## 6. Что передать нам (личным сообщением, не в общем чате)
1. Идентификатор приложения (client_id).
2. Секрет приложения (client_secret).
3. Email HR-сотрудника, который будет исполнителем.
4. Подтверждение, что приложение установлено от служебного пользователя и состоит в группе «Заявки HR».
5. Ответ на вопрос п.3: можно ли указывать постановщика от имени сотрудника.
