# Безопасность портала

## Что сделано в коде
- **SQL-инъекции:** весь доступ к базе идёт через Prisma (запросы параметризованы). Сырые запросы (`$queryRaw`, `$executeRaw` и их Unsafe-версии) запрещены правилом ESLint.
- **XSS:** `dangerouslySetInnerHTML` не используется и запрещён правилом ESLint. Ссылки на файлы принимаются только `https://` или путь внутри сайта (`src/lib/safeUrl.ts`).
- **Данные запросов:** все тела запросов проверяются схемами zod, размер запроса ограничен 1 МБ; параметры адреса (`type`, `limit`, `year`) проверяются.
- **Загрузка файлов:** только для вошедших, до 20 МБ, список разрешённых расширений (без HTML и SVG), проверка содержимого основных форматов, очистка имени, лимит 30 загрузок за 10 минут.
- **Вход:** защита от подбора пароля (5 неудачных попыток на email за 15 минут, 30 попыток с одного IP), одинаковое время ответа для существующих и несуществующих email, пароль до 200 символов.
- **Сессии:** срок 7 дней; роль сотрудника проверяется в базе (с памятью 30 секунд), удалённый или понижённый сотрудник теряет доступ сразу.
- **Временные пароли:** генерируются криптографически случайно (14 символов).
- **Запросы с чужих сайтов (CSRF):** изменяющие запросы к `/api` принимаются только с адреса портала (`src/proxy.ts`).
- **Битрикс:** установка принимает токены только от своего домена и проверяет их у Битрикса; события принимаются только с верным токеном приложения.
- **Заголовки:** запрет встраивания в чужие страницы, nosniff, HSTS, Referrer-Policy, Permissions-Policy.
- **Зависимости:** `npm audit --omit=dev` без уязвимостей, Dependabot проверяет обновления раз в неделю, `engines` разрешает только версии Node с патчами.

## Что нужно на сервере
- Уникальный длинный `NEXTAUTH_SECRET` (отдельный для боевого сервера), `NEXTAUTH_URL` с адресом портала.
- Секреты только в переменных окружения, не в репозитории.
- Только https. Доступ к базе ограничить приложением.
- Регулярные резервные копии базы.
- Раз в неделю смотреть обновления зависимостей и Node.js, перед выкладкой запускать `npm audit --omit=dev`.

## Известные ограничения
- Лимит попыток входа и загрузок хранится в памяти сервера: на одном сервере (Docker на Timeweb) работает полностью, на Vercel в пределах одного экземпляра.
- Файлы в хранилище доступны по прямой ссылке (адрес случайный). Для строго конфиденциальных документов нужны закрытые ссылки с проверкой доступа.
