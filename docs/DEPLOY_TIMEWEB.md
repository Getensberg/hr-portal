# Деплой на Timeweb Cloud (Docker)

Схема: App Platform (сайт собирается из GitHub по `Dockerfile`) + PostgreSQL + S3-хранилище. Всё в одном проекте Timeweb.
Хостинг в России нужен, потому что Битрикс24 недоступен из-за рубежа (с Vercel заявки не доходили до Битрикса: `ConnectTimeoutError`).

## 1. Что создать в Timeweb
1. **База данных** → PostgreSQL. Запомнить хост, порт, пользователя, пароль, имя базы.
2. **Хранилище S3** → новый бакет, тип доступа «публичный». Запомнить endpoint, регион, Access Key, Secret Key, имя бакета.
3. **Приложение** (App Platform) → тип «Docker», репозиторий `Getensberg/hr-portal`, ветка `main`, включить автодеплой. Dockerfile лежит в корне, порт 3000.

## 2. Переменные окружения приложения
| Переменная | Что это |
|---|---|
| `DATABASE_URL` | `postgresql://USER:PASSWORD@HOST:5432/DBNAME` |
| `DIRECT_URL` | то же самое значение (для миграций) |
| `NEXTAUTH_URL` | адрес сайта (технический адрес Timeweb или домен) |
| `NEXTAUTH_SECRET` | длинная случайная строка (можно взять со старого сайта, тогда сотрудников не выкинет из системы) |
| `APP_URL` | тот же адрес сайта |
| `S3_ENDPOINT` | например `https://s3.twcstorage.ru` |
| `S3_REGION` | например `ru-1` |
| `S3_BUCKET` | имя бакета |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | ключи хранилища |
| `S3_PUBLIC_URL` | необязательно: публичный адрес бакета, если отличается от `ENDPOINT/BUCKET` |
| `BITRIX_CLIENT_ID`, `BITRIX_CLIENT_SECRET`, `BITRIX_DOMAIN`, `BITRIX_HR_EMAIL`, `BITRIX_TOKEN_KEY` | интеграция с Битриксом (те же значения, что были в Vercel; ключ `BITRIX_TOKEN_KEY` менять нельзя) |
| `BITRIX_GROUP_ID` | необязательно, ID группы «Заявки HR» |
| `NEXT_PUBLIC_*` | ссылки на соцсети и чаты. Они нужны ещё при сборке, поэтому задайте их и как переменные сборки |

Секреты не коммитить.

## 3. Перенос данных из Neon
1. Резервная копия в панели Neon.
2. `pg_dump "СТРОКА_NEON" --no-owner --no-privileges -Fc -f hr.dump`
3. `pg_restore --no-owner --no-privileges -d "СТРОКА_TIMEWEB" hr.dump`
4. `npx prisma migrate status` (с `DIRECT_URL` на новую базу): все миграции должны быть применены.

## 4. Перенос файлов
Старые файлы лежат в Vercel Blob и в базе хранятся ссылками. Их нужно скачать, залить в S3 и заменить ссылки в базе (скрипт готовится отдельно). До этого старые ссылки продолжат работать, пока не отключён Vercel Blob.

## 5. После запуска
1. Открыть технический адрес, войти, создать тестовую заявку с файлом.
2. В приложении Битрикса сменить адреса на новые: обработчик `/api/bitrix/handler`, установка `/api/bitrix/install`. Разработчик Битрикса переустанавливает приложение.
3. Создать заявку и проверить, что задача появилась в Битриксе.
4. Только потом переключать домен и выключать Vercel.

## 6. Если сборка Docker упала
- Ошибка на `postinstall.js` (Prisma): сервер сборки не достучался до `binaries.prisma.sh`, повторить сборку.
- Ошибка про `DATABASE_URL`: переменные уже подставлены в Dockerfile для сборки, проверьте, что `Dockerfile` не менялся.
